# i18n gap report — bem, nya, fr, zh (week 48, 2026)

**Branch at measure:** `master` @ `32a746a8`  
**Scope:** Customer-facing namespaces only (`admin`, `vendor`, `ai`, `legal` excluded).  
**Locales:** `bem`, `nya`, `fr`, `zh` compared to `packages/i18n/messages/en/*.json`.

## Method

For each locale and namespace we counted:

1. **Missing** — leaf keys present in English but absent in the locale file (entire missing file ⇒ every English key in that namespace counts as missing).
2. **Identical** — key present in the locale file, value byte-identical to English, **longer than 12 characters**, and not excluded as a brand-only token, URL, or ICU-only skeleton (no meaningful translatable prose once ICU placeholders are stripped).

Keys are flattened from namespace JSON (dotted top-level keys plus nested objects). Counts were produced with an offline script in agent scratch space (not committed); the same script was re-run to verify the table below.

## Recommendation (bem & nya)

Pay for human translation in this order:

1. **`checkout`** — **60** strings still missing or English-identical (22 missing, 38 identical). Money path, cart, MoMo/card/COD, gifts, and group checkout for events/services.
2. **`orders`** — **117** strings (113 missing, 4 identical). Post-purchase tracking, escrow copy, refunds, and support hand-offs.

Together that is **177 strings** before tackling `account` (191 gaps) or `catalog` (144). French and Simplified Chinese are in better shape on core shop flows but still need **`services`** (41 missing + ~23 English-identical each) and the missing **`clips`** files if the pilot goes wide.

Do **not** machine-translate in-repo; use this report to scope vendor quotes. `clips` remains English-only in all four locales until dedicated files are added.
