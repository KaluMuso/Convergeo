## Why the existing graph is held

The protected `staging-operation.yml` deploys the candidate, then `e2e.yml` resets and reseeds the canonical synthetic fixtures, then `preflight-e2e-test-otp.mjs` sends a real Supabase Auth OTP request before verifying each hosted test code. A missing or mismatched hosted test-OTP map can call the active `send-sms-otp` hook. That function supports Africa's Talking `live` as well as `sandbox`. A stored test code does not prove the hosted mapping or the provider credential class.

The protected graph now refuses to start deployment unless the repository variables `STAGING_SMS_SANDBOX_ATTESTED=true` **and** `STAGING_TEST_OTP_MAP_ATTESTED=true` are set by the owner after checking the corresponding hosted settings. The E2E preflight checks the same attestations before any OTP request. Leave both unset while SMS sandbox credentials are unavailable. These variables are attestations, not a technical read of Supabase secrets; setting them without checking hosted configuration is unsafe.
