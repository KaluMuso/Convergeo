First candidate invariant gap from this trace: `process_webhook_event` uses the event's merchant reference to find a payment, then trusts `collection.successful` without matching the signed payload's amount/currency/provider reference to the expected payment. The poller and sweeper likewise use a successful provider status without matching the returned collection identity. A signed but wrong-amount observation may therefore credit the full checkout. This must be demonstrated with a real PostgREST/API/database drill before repair.
