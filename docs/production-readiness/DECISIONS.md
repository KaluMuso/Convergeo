## DEC-002 — Database Authorization Architecture

| Field                               | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Decision ID**                     | DEC-002                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Question**                        | Where is access control enforced — RLS, application layer, or both?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Repository finding**              | **Defense-in-depth: Supabase Auth JWT + Postgres RLS + FastAPI role/ownership checks.** RLS enabled and forced on core tables (~90 tables). Money/ledger tables have RLS with **no client write policies** (service-role only). API loads roles from `user_roles` table (not JWT claims alone). Admin routes use `require_role("admin", "superadmin", "moderator")`. Vendor scope via DB-sourced `vendors.owner_user_id`. Internal cron routes use `X-Internal-Token` per concern. Custom access token hook exists in migration `0051` but is **commented out** in `supabase/config.toml`. |
| **Evidence**                        | `services/api/app/core/auth.py` (JWKS verify, `user_roles` load); `supabase/migrations/0002_identity_vendors.sql`, `0006_money.sql`, `0064_force_rls_launch_tables.sql`; `services/api/tests/rls/` (8 modules); `0086_cart_line_price_guard.sql` (revokes client cart item writes).                                                                                                                                                                                                                                                                                                        |
| **Classification**                  | **CONFIRMED_BY_REPOSITORY** (dual enforcement model)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Current repository architecture** | RLS on ~90 tables + FastAPI `user_roles` checks + `tests/rls/` matrix (Batch 0.5: **RLS CI TRUSTWORTHY** on `master`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Long-term product decision**      | CAN-OPS-001 — tenant cryptographic isolation via RLS; CAN-ORD-002 — client cart writes blocked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Current recommendation**          | Never assume RLS alone or API alone; both must be maintained. Enable custom access token hook only after explicit ops decision (FD-03 in consolidated docs).                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Remaining product decision**      | **PRODUCT_DECISION_REQUIRED:** Whether to enable `custom_access_token_hook` (0051) vs continue DB-only role loading. Admin RBAC granularity (FD-02).                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Implementation consequence**      | New tables need RLS policies + API authz tests; mutating endpoints need service-role for money paths.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
