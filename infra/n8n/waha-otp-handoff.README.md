Supabase Auth remains the only code generator, verifier, expiry and rate-limit authority. n8n and WAHA transport the code only. The repository JSON is an inactive source template. A separately bound hosted copy had one owner-approved staging test on 2026-10-09; the owner disabled its send path and staging switches after the receipt check failed. This source change does not edit or reactivate that copy.

Reverify the actual runtime, node parameters, and private credential bindings before any new import or test. Do not move the HMAC secret into a workflow parameter or Code node to bypass compatibility checks.

`waha-otp-handoff.json` is generated by `node infra/n8n/build-waha-otp-handoff.mjs`. It starts with `active: false` and its WAHA send node `disabled: true`. These settings do **not** prove zero OTP persistence: n8n may store in-flight execution data containing the webhook body before normal pruning. Retention, hard deletion, backups, and access controls need review before any real OTP test. The template holds **credential references only**. Do not insert tokens or keys into JSON or Code nodes. Keep the established WAHA send-only credential private; this source does not read or reproduce its key.

## Contract and replay reservation

The Edge Function sends `{version,requestId,timestamp,deadline,phone,otp}` to a dedicated HTTPS n8n webhook with Header Auth and `X-Convergeo-OTP-Signature`. The signature is lowercase hex HMAC-SHA256 over `v1\n<timestamp>\n<requestId>\n<deadline>\n<phone>\n<otp>` using a **separate** secret. The n8n Crypto node computes the HMAC from a credential. The Code nodes validate shape, time, recipient and digest before the send node. The Edge Function accepts only a 200 response of exactly `{accepted:true,requestId:<same id>}` after WAHA returns a message ID.

The acceptance node supports both a bounded flat `id` and the observed WAHA engine response with `key.id`. For the nested shape it also requires `key.fromMe === true`, `key.remoteJid` to equal the signed recipient as an individual `@c.us` chat, and `status === 'PENDING'`; a conflicting flat ID is rejected. Both shapes must pass the original deadline check and 8–256 character ID bound. `PENDING` alone is never proof of acceptance, and the receipt does not claim handset delivery. The owner-redacted failed execution showed `key.id` but no top-level `id`, explaining the rejected receipt; only synthetic values appear in tests. A hosted copy must receive a reviewed **Check WAHA Acceptance** Code-node replacement while preserving its existing credentials, settings, and other nodes. This repository change performs no hosted edit or new send.

The disabled WAHA HTTP Request v4.2 node explicitly refuses redirects and disables credential forwarding across origins. Both settings are required because [n8n 2.30.6 follows redirects by default for v4 nodes and defaults cross-origin credential forwarding on for versions before 4.4](https://github.com/n8n-io/n8n/blob/n8n@2.30.6/packages/nodes-base/nodes/HttpRequest/V3/HttpRequestV3.node.ts). Synthetic 307/308 response fixtures cannot produce an accepted OTP receipt.

The `Reserve Request ID` Postgres node uses an atomic `INSERT ... ON CONFLICT DO NOTHING RETURNING` before WAHA. A duplicate produces no downstream item, so the send does not run. Its restricted database must have this table created separately by an authorized operator; **no database command was executed for this draft**:

```sql
CREATE TABLE otp_delivery_replay (
  request_id text PRIMARY KEY CHECK (length(request_id) BETWEEN 8 AND 64),
  expires_at timestamptz NOT NULL
);
```

Use a dedicated Postgres credential with `INSERT` on this table and `SELECT(request_id)` for the `RETURNING` and conflict clause ([PostgreSQL privilege rule](https://www.postgresql.org/docs/current/sql-insert.html)). No other table access is needed. The stored values are random request IDs and expiry times; no phone, OTP, or message body. Retain reservations for at least one day, then purge through a separate authorized maintenance path. A database outage must stop delivery. A reservation followed by WAHA failure also blocks retry of the _same_ request ID; requesting a fresh Supabase OTP may create another ID. Concurrent duplicates are serialized by the database primary key. This does not prevent a new signed request ID from producing another message, nor prove handset delivery or exactly-once behavior.

The [Supabase Send SMS Hook](https://supabase.com/docs/guides/auth/auth-hooks/send-sms-hook) treats empty HTTP 200 as success and has a five-second deadline. The Edge handoff has a 2.8-second timeout and no in-function retry. A timed-out or lost n8n response is uncertain even if WAHA accepted the message; the code fails closed. The [n8n Webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/) and [Crypto](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.crypto/) nodes underpin the template; [Postgres query parameters](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.postgres/) bind the request ID and deadline.
